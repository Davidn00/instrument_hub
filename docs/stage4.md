# Stage 4 — Signal Processing Pipeline

## Objective

Stage 4 introduces the numerical signal-processing layer of InstrumentHub.

The objective is to provide reusable processing components for measurements and signals generated by simulated or real instruments without coupling numerical processing to FastAPI or the acquisition layer.

The processing layer provides:

* Standard measurement representation.
* Vectorized NumPy processing.
* Digital filtering with SciPy.
* Frequency-domain analysis.
* Spectral analysis.
* Initial anomaly detection methods.

The architecture is designed to support future offline analysis as well as real-time processing of acquired measurements.

---

# Architecture

The Stage 4 processing flow is:

```text
Instrument
     |
     v
Acquisition
     |
     v
Measurement
     |
     v
Signal / NumPy array
     |
     +----------------------+
     |                      |
     v                      v
Statistics               Filters
     |                      |
     +----------+-----------+
                |
                v
        Spectral Analysis
                |
                v
       Anomaly Detection
```

The processing package is intentionally independent from FastAPI.

This allows the same processing functions to be used by:

* REST services.
* Acquisition services.
* Background workers.
* Tests.
* Offline analysis.
* Future real-time pipelines.

# Part 11 — Measurement Model

## Objective

Stage 4 standardizes the representation of an individual measurement.

The canonical structure is:

```text
Measurement
├── timestamp
├── device_id
├── channel
├── value
├── unit
├── quality
└── metadata
```

## Fields

### `timestamp`

Timestamp associated with the measurement.

The model normalizes naive timestamps to UTC.

### `device_id`

Identifier of the instrument that produced the measurement.

### `channel`

Logical channel or sensor source associated with the value.

Examples:

```text
ECG-I
ECG-II
temperature
pressure
accelerometer-x
accelerometer-y
```

### `value`

Numeric measurement value represented as `float`.

### `unit`

Physical unit associated with the value.

Examples:

```text
°C
kPa
mV
V
Hz
nm
```

### `quality`

Quality classification associated with the measurement.

Supported values:

```text
GOOD
SUSPECT
BAD
UNKNOWN
```

### `metadata`

Additional contextual information that should not be part of the core measurement contract.

Example:

```python
{"measurement_type": "ecg", "sample_rate": 500, "source": "simulated"}
```

## Backward compatibility

Stages 2 and 3 used:

```text
sensor_id
measurement_type
```

The Stage 4 model maintains compatibility with those fields.

The mapping is:

```text
sensor_id
    ↓
channel

measurement_type
    ↓
metadata["measurement_type"]
```

Compatibility properties remain available:

```python
measurement.sensor_id
measurement.measurement_type
```

This allows the acquisition and simulation layers from previous stages to continue working without unnecessary modifications.

# Part 12 — NumPy Processing

## Objective

The processing layer uses NumPy for vectorized numerical operations.

All processing functions operate on one-dimensional finite numeric arrays.

The main validation helper is:

```python
as_float_array()
```

It converts input sequences into NumPy floating-point arrays and rejects:

* Empty arrays.
* Multidimensional arrays.
* NaN values.
* Infinite values.

## Normalization

Two normalization methods are available.

### Z-score normalization

```python
normalize_zscore()
```

The output is centered around zero with unit standard deviation for non-constant signals.

For constant signals, the implementation returns zeros instead of producing undefined values.

### Min-max normalization

```python
normalize_minmax()
```

The signal is linearly mapped into a configurable range.

Default range:

```text
[0, 1]
```

---

# Statistical analysis

The following operations are available:

```text
mean()
standard_deviation()
rms()
minimum()
maximum()
statistics()
```

The `statistics()` function returns a `SignalStatistics` object containing:

```text
mean
standard_deviation
rms
minimum
maximum
number_of_samples
```

Example:

```python
result = statistics(samples)

print(result.mean)
print(result.standard_deviation)
print(result.rms)
print(result.minimum)
print(result.maximum)
```

---

# Sliding windows

Signal processing often requires local windows rather than processing an entire signal at once.

The function:

```python
sliding_windows()
```

creates overlapping windows without padding.

Example:

```python
windows = sliding_windows(
    samples,
    window_size=100,
    step=20,
)
```

This functionality is particularly important for:

* Streaming signals.
* ECG analysis.
* EMG analysis.
* Rolling anomaly detection.
* Future feature extraction.

# Part 13 — Digital Filters

## Objective

Stage 4 introduces digital filtering using SciPy.

The available filters are:

```text
Moving average
Butterworth
Low-pass
High-pass
Band-pass
Notch
```

---

## Moving average

Function:

```python
moving_average()
```

The moving average is a simple smoothing filter useful for reducing short-term noise.

Example:

```python
filtered = moving_average(
    samples,
    window_size=5,
)
```

---

# Butterworth filter

The general-purpose Butterworth implementation is:

```python
butterworth_filter()
```

Supported filter types:

```text
lowpass
highpass
bandpass
```

The implementation uses second-order sections and zero-phase filtering.

This is important for offline signal analysis because phase distortion is avoided.

---

# Low-pass

Function:

```python
low_pass_filter()
```

Example:

```python
filtered = low_pass_filter(
    samples,
    sampling_rate=1000,
    cutoff=40,
)
```

A low-pass filter attenuates frequencies above the configured cutoff.

---

# High-pass

Function:

```python
high_pass_filter()
```

Example:

```python
filtered = high_pass_filter(
    samples,
    sampling_rate=1000,
    cutoff=0.5,
)
```

A high-pass filter attenuates frequencies below the configured cutoff.

---

# Band-pass

Function:

```python
band_pass_filter()
```

Example:

```python
filtered = band_pass_filter(
    samples,
    sampling_rate=1000,
    low_cutoff=5,
    high_cutoff=40,
)
```

A band-pass filter preserves the specified frequency range while attenuating frequencies outside it.

---

# Notch

Function:

```python
notch_filter()
```

The notch filter is designed to remove a narrow frequency component.

A common instrumentation application is suppression of mains interference:

```text
50 Hz
```

or:

```text
60 Hz
```

Example:

```python
filtered = notch_filter(
    samples,
    sampling_rate=1000,
    frequency=50,
)
```

The filter uses an adjustable quality factor.

---

# Filtering pipeline

A signal can be processed through multiple filters:

```text
Raw signal
    |
    v
Moving average
    |
    v
High-pass
    |
    v
Low-pass
    |
    v
Notch
    |
    v
Filtered signal
```

The exact pipeline is application-dependent and will be configurable through a future processing service.

# Part 14 — FFT and Spectral Analysis

## Objective

Stage 4 introduces frequency-domain analysis.

The spectral processing layer provides:

* FFT.
* Amplitude spectrum.
* Dominant frequency.
* Power spectral density.
* Harmonic detection.

---

# FFT

Function:

```python
fft_spectrum()
```

The function calculates a single-sided real FFT.

The returned `FFTResult` contains:

```text
frequencies
amplitudes
```

Example:

```python
result = fft_spectrum(
    samples,
    sampling_rate=1000,
)

frequencies = result.frequencies
amplitudes = result.amplitudes
```

The resulting representation is:

```text
Time Domain
     |
     v
    FFT
     |
     v
Frequency Domain
```

---

# Dominant frequency

Function:

```python
dominant_frequency()
```

It identifies the frequency bin with the greatest amplitude.

Example:

```python
frequency = dominant_frequency(
    samples,
    sampling_rate=1000,
)
```

The DC component is excluded by default.

This is useful for:

* Periodic signals.
* Vibration analysis.
* Sensor oscillations.
* Instrument diagnostics.
* Synthetic signal validation.

---

# Power Spectral Density

Function:

```python
power_spectral_density()
```

PSD is estimated using Welch's method through SciPy.

The returned `PSDResult` contains:

```text
frequencies
power
```

Example:

```python
result = power_spectral_density(
    samples,
    sampling_rate=1000,
    nperseg=500,
)
```

Welch's method provides a more stable spectral power estimate than relying on a single raw FFT.

---

# Harmonic detection

Function:

```python
detect_harmonics()
```

The function searches around integer multiples of a fundamental frequency.

Example:

```python
harmonics = detect_harmonics(
    samples,
    sampling_rate=1000,
    fundamental_frequency=50,
    max_harmonic=5,
)
```

Potential harmonic frequencies:

```text
50 Hz
100 Hz
150 Hz
200 Hz
250 Hz
```

A frequency tolerance is used because FFT bins do not necessarily fall exactly on the theoretical harmonic frequencies.

# Part 15 — Anomaly Detection

## Objective

Stage 4 introduces the first statistical anomaly-detection layer.

The initial implementation is intentionally lightweight and dependency-efficient.

The following methods are available:

```text
Threshold
Z-score
IQR
Rolling Z-score
```

More advanced machine-learning methods are reserved for a future stage.

---

# Threshold detection

Function:

```python
threshold_anomalies()
```

The function flags measurements outside configured limits.

Example:

```python
anomalies = threshold_anomalies(
    samples,
    lower=0,
    upper=100,
)
```

The result is a Boolean NumPy array.

---

# Z-score detection

Function:

```python
zscore_anomalies()
```

The method identifies samples whose absolute standardized deviation exceeds the configured threshold.

Example:

```python
anomalies = zscore_anomalies(
    samples,
    threshold=3.0,
)
```

For a constant signal, no anomalies are generated because the standard deviation is zero.

---

# IQR detection

Function:

```python
iqr_anomalies()
```

The method uses Tukey's IQR fences:

```text
Lower fence = Q1 - multiplier × IQR

Upper fence = Q3 + multiplier × IQR
```

The default multiplier is:

```text
1.5
```

Example:

```python
anomalies = iqr_anomalies(
    samples,
    multiplier=1.5,
)
```

---

# Rolling Z-score

Function:

```python
rolling_zscore_anomalies()
```

This method compares the current sample with statistics calculated from previous samples.

Example:

```python
anomalies = rolling_zscore_anomalies(
    samples,
    window_size=50,
    threshold=3.0,
)
```

The current sample is excluded from the reference window.

This design makes the method suitable for future streaming processing.

Conceptually:

```text
Previous samples
       |
       v
+------------------+
| Rolling window   |
+------------------+
       |
       v
mean + std
       |
       v
Current sample
       |
       v
Anomaly?
```

# Compatibility

Stage 4 is designed as an incremental extension of Stages 1–3.

The acquisition layer does not need to know how signals are processed.

The processing layer does not need to know whether a measurement originated from:

* A simulated instrument.
* Serial hardware.
* TCP hardware.
* MQTT hardware.
* A dataset.

This separation allows future implementations to connect acquisition and processing without changing the underlying processing algorithms.

---

# Current limitations

Stage 4 intentionally does not yet implement:

* Processing service orchestration.
* Persistent processed-signal storage.
* Real-time processing workers.
* Processing configuration persistence.
* Advanced machine-learning anomaly detection.
* Visualization dashboards.
* End-to-end acquisition-to-processing streaming.

These capabilities belong to subsequent stages.

Scikit-learn is intentionally not required by the first anomaly-detection implementation.
